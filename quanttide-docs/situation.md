# 情境（situation）

情境 = 具体处境的结构化描述，字段直接采用 Endsley 情境意识框架：
**感知 L1**（发生了什么）→ **理解 L2**（如何解释）→ **预测 L3**（将如何演化）→ **决策**（要做什么）。
文末附情境间关系（support 支持 / conflict 冲突）。

> 状态图例：未标注 = 已确认；🔄 进行中；⚠️ 开放问题。来源见文末。

## 1. 文档云结构治理 🔄

- **感知 L1**：文档量大且链接容易乱连；历史上腾讯云文档乱跳链接的体验恶劣；AI 参与写作后格式混乱更明显。
- **理解 L2**：核心是全局结构管理——文档云要能计算并预警链接混乱之处；可视化关系图不止用于看，还要支撑决策治理。
- **预测 L3**：树状结构 + 显式链接约定 → 预警机制识别混乱点 → 关系图驱动持续治理 → 人访问时不再出问题。
- **决策**：以树状优先、链接谨慎为原则建设文档云的结构治理能力。

## 2. 智能文档工程化 🔄

- **感知 L1**：文档格式（表格、列表、正文）可被解析器解析出具体数字；AI 生成内容格式多且乱。
- **理解 L2**：格式定量分析 + 阅读体验反评 = 有效的质量指标；文档工程关心阅读负担，叙事工程关心 storytelling。
- **预测 L3**：指标成熟 → 告知哪些内容需要优化 → 与阅读负担检测形成文档质量前置过滤。
- **决策**：把格式定量分析作为文档质量的评估手段推进。

## 3. 规则文档分层沉淀 🔄

- **感知 L1**：工作日志承载着大量规则性内容；章程、手册、教程混在一起容易归属不清。
- **理解 L2**：手册（稳定流程、工具无关）、教程（工具相关、最后环节）、章程（质量检查标准、最稳定）三分；「文档格式」章程经论证归属文档工程。
- **预测 L3**：日志 → 总结沉淀为章程/手册 → 规则类制品与工作语境（九宫格）的关系明确。
- **决策**：按稳定性分层沉淀规则文档，日志作为上游素材。

---

## 情境关系

- **文档云结构治理** support **智能文档工程化**：结构治理提供链接与关系的底账，智能评估才有上下文。
- **智能文档工程化** support **文档云结构治理**：格式定量指标是预警机制的输入之一。
- **规则文档分层沉淀** ← **文档云结构治理**（conflict）：治理强调树状稳定，沉淀要求内容持续流动更新，存在张力。
