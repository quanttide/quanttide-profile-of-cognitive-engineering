# 图式（schema）

图式 = 可复用、可推理的心智模型。每条图式足够小、足够精确，才能被识别和复用。
字段直接采用 CWA 抽象层级与活动理论：**目的**（为何激活 · functional purpose）、**实体**（概念与属性 · 本体论）、**手段-目的**（条件→结果 · means-ends）、**约束**（适用/排除 · CWA constraints）、**行动**（意图→行动 · 活动理论）。

> 状态图例：未标注 = 已确认；🔄 进行中；❓ 待验证。来源见文末。

## 1. 智能文档评估 🔄

- **目的**：判断一篇文档的内容质量、是否需要优化时。
- **实体**：文档格式（表格/列表/正文）、文档解析器、定量分析、人类阅读体验。
- **手段-目的**：解析格式 → 定量分析 → 以阅读体验反向评估 → 输出优化信号。
- **约束**：AI 生成内容格式多且乱，天然是待优化信号；不关心文本内核（那是叙事工程）。
- **行动**：想评估内容质量 → 用格式定量指标衡量阅读负担。

## 2. 树状优先、链接谨慎 🔄

- **目的**：决定文档之间是否建立链接时。
- **实体**：树状结构、网状连接、链接、显式约定。
- **手段-目的**：默认保持树状 → 网状连接需业务规定明确要求 → AI 删除不必要链接，以显式约定维护工作流。
- **约束**：基于智能与知识，而非让链接乱连；乱跳的链接会淹没正事（腾讯云文档的教训）。
- **行动**：想引用 → 先问业务上是否明确需要；不明确就不链。

## 3. 三档关系层级 🔄

- **目的**：为文档之间的关系建模时。
- **实体**：article 内部关系、book 级别关系、library 级别关系（含跨库）。
- **手段-目的**：区分三个档次的关系 → 分别界定维护与治理方式。
- **约束**：三个档次的边界尚未充分搞清楚。
- **行动**：想治理文档结构 → 先分清关系发生在哪一档。

## 4. 手册-教程-章程三分

- **目的**：为规则类文档选型时。
- **实体**：手册（稳定流程、与工具无关）、教程（工具相关、最后环节）、章程（质量检查标准、最稳定）。
- **手段-目的**：按稳定性分层 → 流程进手册、操作进教程、检查标准进章程。
- **约束**：适用于标准化体系文档的分工。
- **行动**：想沉淀规则 → 先判断内容属于哪一层稳定性。

## 5. HTML 中转对齐 🔄

- **目的**：对 Markdown 文档做结构校对时。
- **实体**：Markdown（信息内容）、HTML（可读的信息结构）、JSON（进一步结构化提取）。
- **手段-目的**：Markdown 转 HTML → 根据 HTML 纠正结构/叙事方向 → 反向修改 Markdown → 需要时再提取 JSON。
- **约束**：HTML 用于展示信息结构，不改变内容本身。
- **行动**：想检查文档结构 → 转成 HTML 看，发现问题回改 Markdown。
