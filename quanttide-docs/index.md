# 量潮文档（quanttide-docs）认知档案

本档案交付对「文档工程」的认知状态与思考状态：我们对文档这件事理解到了什么程度——文档阅读负担、结构治理与标准前置。

> 未标注 = 已确认；🔄 进行中；❓ 待验证；⚠️ 开放问题。每次从 journal 摘要后更新本档案。

## 术语

- **智能文档工程**：分析文档格式（表格、列表、正文等）→ 文档解析器解析 → 定量分析 → 按人类阅读体验反向评估内容质量。
- **文档阅读负担**：文档工程关心「文档阅读本身的负担是不是重」，而非文本内核（文本内核属叙事工程）。
- **手册 / 教程 / 章程**：手册记录相对稳定、与工具无关的流程；教程可含工具相关内容（最后环节）；章程记录质量检查标准（最稳定的东西）。
- **文档层级**：article 内部关系、book 级别关系、library 级别关系——三个档次需充分区分。
- **树状结构**：文档默认保持树状；网状连接需谨慎，仅在业务规定明确要求时建立链接。

## 核心目标

- **降低文档阅读负担**：以阅读体验为基准，定量评估内容是否需要优化（AI 生成内容格式多且乱，是天然的待优化信号）。
- **全局文档结构治理**：文档云帮助管理全局文档结构，计算并预警链接混乱之处，避免人访问时出问题。
- **关系可视化与决策治理**：像飞书那样的文档关系可视化图，且不止于看——用它做决策，鼓励治理与维护。

## 当前认知状态

- **智能文档工程已定义**（08-20）：格式解析 → 定量分析 → 阅读体验反评，可作为内容质量指标。
- **文档 vs 叙事的分工**：叙事工程关心 storytelling；文档工程关心阅读负担等基础指标。
- **「文档格式」章程归属文档工程**（08-26，Kimi 论证）：文档工程与叙事工程的边界有了判例。
- **链接治理原则**（09-04）：不随便引用、AI 删除不必要链接、以显式约定维护工作流——基于智能与知识而非乱连。
- 🔄 **article / book / library 三档关系**（09-04）：文档以上的关系层级需充分搞清楚。
- 与九宫格的关系：章程/手册等规则类制品可由工作日志逐步总结沉淀（工作语境 → 精炼）。

## 当前焦点与下一步

- 🔄 **文档云的结构治理能力**：全局结构管理、链接混乱预警、关系可视化图并支撑决策。
- 🔄 **三档关系建模**：article 内部、book 级别、library 级别（含跨库）关系的界定。
- ⚠️ **网状连接的边界**：哪些业务场景明确需要链接，需要显式约定。

## 待验证与张力

- ❓ 智能文档工程的定量指标如何定义，才能与人类阅读体验稳定对应？
- ❓ 链接预警的判定标准：混乱 vs 有价值的网状连接，边界如何量化？
- ⚠️ 文档关系可视化「看」与「用于决策治理」之间的产品形态差距。
