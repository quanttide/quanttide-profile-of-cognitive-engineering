# 工作流ID

端侧ID默认使用UUID5生成。这样DSL语法写的工作流文件可以被看作拥有一个隐式ID，在进入端侧系统初始化的时候显性化。

UUID5的生成算法的输入参数为初始工作区ID和初始工作流名称。如果未来进入端侧以后再改名或者更换工作区，UUID5不会再修改。

## [已通过] 典型情境1：离线创建

用户在离线状态下用 DSL 写了一个工作流文件，此刻没有端侧系统可用。UUID5 是纯函数，隐式 ID 在文件写下的一刻就已经数学上确定，只是尚未被系统认识——显性化的时机是端侧初始化，不是联网时刻。多个设备各自离线创建、后同步时，ID 不需要协商：这是选择确定性 ID 而非随机 ID 的根本理由。因此 DSL 文件中禁止手写 ID，系统以计算值为准。

## [待评估] 典型情境2：同名重建

用户删掉一个工作流，又手动重建了同名同工作区的一个。UUID5 的纯函数性使重建生成相同的 UUID，系统无法区分「复活」与「新建」：删除时挂在 ID 上的历史数据（订阅、执行记录）会被重建对象继承——可能是历史找回的特性，也可能是旧任务复活的事故。删除语义需要明确：是软删除保留墓碑，还是允许同 ID 复活，应在进入端侧实现前于 spec 中约定。
