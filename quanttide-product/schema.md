# 图式（schema）· 产品

图式 = 可复用、可推理的心智模型。字段直接采用 CWA 抽象层级与活动理论：**目的**（为何激活 · functional purpose）、**实体**（概念与属性 · 本体论）、**手段-目的**（条件→结果 · means-ends）、**约束**（适用/排除 · CWA constraints）、**行动**（意图→行动 · 活动理论）。

> 状态图例：未标注 = 已确认；🔄 进行中；❓ 待验证。来源见文末。

## 1. 文档先行

- **目的**：制定产品研发策略时。
- **实体**：文档、海量文本、平台。
- **手段-目的**：从文档出发整理海量文本 → 流程靠单个人维护不下去 → 开始做平台。
- **约束**：文本整理流程未到极限前不做平台。
- **行动**：先基于文本整理，再平台化。

## 2. 可视化方法

- **目的**：展示需求、产品需求等难以直接展示的内容时。
- **实体**：需求、图（任务地图、产品地图、事件风暴）。
- **手段-目的**：需求难用可视化展示 → 画图 → 清晰表达。
- **约束**：适用于难以可视化的工作；方法本身已确认正确。
- **行动**：用图表达需求。

## 3. 交付边界

- **目的**：划分产品研发职责时。
- **实体**：编程、产品、DevOps、代码与测试文档。
- **手段-目的**：编程交付代码和测试文档 → 产品判断研发状态与水平 → DevOps 维护版本迭代发布。
- **约束**：各有侧重，不越界。
- **行动**：按边界分工：管交付的管交付，管认知对齐的管认知对齐。
