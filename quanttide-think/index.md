# 量潮思考（quanttide-think）认知档案

本档案交付对「思考」的认知状态与思考状态：我们对思考这件事理解到了什么程度。思考模式、思考方法是再上一个层次的内容。

> 未标注 = 已确认；🔄 进行中；❓ 待验证；⚠️ 开放问题。每次从 journal 摘要后更新本档案。

## 术语

- **思考云**：与人类同步思考的结构化系统——输入原始信息，AI 结构化分析（事实/感受/行动…），产出降维后的干净结构。
- **认知负担 / 认知摩擦**：理解与行动之间的阻力，减少它是认知工程的核心目标。
- **insight / intention**：insight 是思考的核心结果（与思考云对应度更高）；intention 是意图。
- **档案 / 归档**：档案 = 交付认知状态与思考状态的结构化记录；归档 = 知识生命周期终点。
- **对抗性协同进化**：明确需求后互相举证、互相质疑，驱动系统与认知共同收敛。
- **图示 / 情境**：档案中值得保留的两类核心内容（想法、意图可清空），定义待精确化。
- **认知密度**：信息的有效度；检测工具在研，与认知负担检测融合为前置过滤器。

## 核心目标

- **系统性减少认知负担**：认知工程的核心，也是思考云存在的意义——从个人开始，最终帮助团队规模化减少负担。
- **认识第二大脑**：认知工程解决的是人类的认识问题；档案作为认知模式的记录，天然透明化，无需纠结「建模建什么」。
- **建立全局**：认知工程日志记录领域层级的全局（比产品运营高一个层次），看整个体系框架。
- **对大批量想法才有用**：需要回到认知科学、心理学，构建能区分人类日常活动的更基础结构。

## 思考云的形态

- 与人类**同步进行思考**，通过结构化方式让 AI 思考。
- 输入原始信息，AI 结构化分析：哪些是事实、哪些是感受、哪些是行动（清单可继续补全）。
- 对想法**加工、结构化、分门别类**——从混沌中找到干净的降维结果。
- 🔄 批处理与流处理没有区别，最终要精简出**支持连续思考的信息结构**，当前结构还不够精细。
- 与 **insight 对应度高于 intention**：insight 是思考的核心结果。
- 思考侧重**认知结构**，与沟通区分开；需要沟通的用沟通。

## 交付物：认知工程档案

- 交付**认知状态与思考状态**——「对这个领域的理解到了什么程度」，标准化结构即可。
- 具备明确界限：哪些留在档案里，哪些归档。
- 想法、意图类内容可逐渐清空，保留**图示与情境**即足够；档案体现认知模式的记录。
- 图式与情境已提炼：`schema.md`（心智模型）、`situation.md`（处境与推演）。

## 日志方法

- 领域日志记录**领域层级全局**；领域交叉性大、边界弹性，不纠结归属，后续可再整理或跨日志加工。
- **不是所有日志都对思考有用**：深度思考存在于明确领域日志的认知、观察之中；人类提供认知与观察，AI 负责处理。
- **日记记在哪没关系**：想到相关话题时把日志整合进去增加上下文；原始日记是最丰富的资源。
- 产品想法独立进**具体产品的研发日志**。
- 认知评估指标：**清楚/不清楚**——清楚的不用再想，不清楚的继续思考。

## 当前认知状态

- **认知在收敛**：系统状态不断向高层次收敛，看到了更完整的结构；对抗性协同进化的模式已搭建。
- **内外边界空前清晰**：核心想法私有化，对外面向市场观察；领域向内、业务向外。
- **认知摩擦大幅降低**：敢于大踏步上线产品（一天两三个），想到立刻做出来；每个新产品增长一块元认知。
- 阶段判断：摊子已铺开（第一阶段），现在进入**第二阶段——向领域内部集中信息，并与其他领域关联**。
- 旧格式（`quanttide-founder` 周快照）是早期实验/脚手架，**格式废弃，从本档案重新开始**。

- 🔄 **从日志到档案的提炼**：验证「图示与情境能否摘出来」——若能，旧 4 层结构就向新结构演化。
